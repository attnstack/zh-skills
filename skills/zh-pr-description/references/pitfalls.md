# Pitfalls：zh-pr-description

## [2026-10] 逐文件复述 diff

- 症状：改动节写了 12 条「修改了 xxx.ts / 新增了 yyy.ts」——reviewer 自己会看 diff，这是浪费注意力。
- 正确处理：按变更意图归并（如「拦截器层统一处理 401」），文件名只在必要时出现。

## [2026-10] 测试节写「本地跑过」

- 症状：无法复核的口头验证等于没验证。
- 正确处理：写清命令、环境、结果（如 `npm run test:auth` 12 passed）。

## [2026-10] BREAKING 埋在正文中间

- 症状：破坏性变更写在第三段，下游调用方没看到，合入后调用崩溃。
- 正确处理：破坏性变更放「背景」第一行，加 `**BREAKING**` 标记与迁移说明。
