# Pitfalls：zh-code-review

## [2026-10] 只看 diff 不看调用方

- 症状：函数签名改了参数顺序，diff 内部一致，所有调用点全崩——评审通过后 CI 才爆。
- 正确处理：改签名/语义时全局搜调用方，把受影响的调用点列进评审意见。

## [2026-10] 「我会这么写」型意见

- 症状：没有指出任何问题，只是风格偏好不同，作者不服，评审变吵架。
- 正确处理：写不出「为什么是问题 + 触发条件」就降为 nit 或不提。

## [2026-10] P0 泛滥

- 症状：所有意见都标 P0，分级失去信号意义，作者开始无视 P0。
- 正确处理：P0 严格等于「阻塞合入的缺陷」，其余宁低勿高。
