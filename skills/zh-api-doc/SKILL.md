# 接口文档生成

接口文档的读者是「要调这个接口的人」：他需要知道传什么、返回什么、错了怎么办。

## 工作流程

1. 输入优先级：OpenAPI/Swagger 定义 > 路由处理函数代码 > 请求样例；从定义出发，代码只用来补缺；
2. 每个接口按下方模板生成；字段说明优先取注释/描述，没有就标注「待补充」而不是编造；
3. 枚举值、示例值必填——没有示例的字段表等于没写。

## 单接口模板

```markdown
## POST /v1/orders
一句话说明用途与前置条件（权限/幂等性）。

### 请求参数
| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|

### 响应
| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|

### 错误码
| code | 含义 | 处理建议 |
|---|---|---|
```

## 硬性规则

1. 「必填」必须有依据（代码校验/OpenAPI required），不确定就标「待确认」，禁止猜；
2. 错误码节必须有——只写 200 的接口文档是半成品；至少覆盖参数错误与权限错误；
3. 时间字段写清时区与格式（`ISO8601，UTC` 或 `Unix 秒`）；
4. 分页接口必须写清 `total` 的口径与是否有下一页的判定方式。
