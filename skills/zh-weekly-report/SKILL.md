# 周报生成

周报的读者是要做资源决策的人：干完什么是事实，风险要人帮忙是重点。

## 工作流程

1. 收集素材：`git log --author=我 --since=本周`、项目管理工具的事项状态、会议纪要；
2. 按「结果 → 风险 → 计划」组织，**风险节不许空着**——没风险就写「无，验证依据是 X」；
3. 数字优先：完成率、遗留 bug 数、进度百分比，没有就写明「按事项数统计」；
4. 长度控制：正文 ≤ 15 行，细节用附注或链接。

## 输出模板

```markdown
# 周报 <姓名> <日期范围>
## 本周进展
- <完成的里程碑级事项>：<一句话结果>（数字/链接佐证）
## 风险与求助
- <阻塞项>：影响是什么，需要谁在什么时候做什么
## 下周计划
- <按优先级 ≤ 3 项，每项有可验收标准>
```

## 硬性规则

1. 写「结果」不写「过程」：`完成网关限流灰度 10%，P99 从 2.1s 降到 1.4s`，
   不是「本周在做限流优化」；
2. 风险必须带「需要什么支持」，单纯吐槽不是风险项；
3. 未完成事项如实写「未完成 + 原因」，不挪到下周装新事项；
4. commit 列表只是素材来源，机械罗列 commit 是最低级的周报形态。

## 常见错误

先读 `references/pitfalls.md`。特别注意：流水账、风险节写「一切正常」却没有任何验证依据。
