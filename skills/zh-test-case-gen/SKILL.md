# 测试用例生成

用例的价值在「打破实现」：正常路径谁都会写，边界与异常才是用例表的主要产出。

## 工作流程

1. 从函数签名/需求提取：输入域（类型、范围、格式）、输出约定、副作用（写库/发请求）；
2. 按三类生成用例：正常（≥2 条代表值）、边界（每类输入域的端点）、异常（非法/缺失/极端）；
3. 每个用例必须写「预期结果」且可判定——「返回合理」不算预期；
4. 输出用例表 + 覆盖说明（哪些分支没覆盖到，为什么）。

## 用例表格式

| 编号 | 类型 | 输入 | 预期结果 | 覆盖点 |
|---|---|---|---|---|

## 硬性规则

1. 边界值双侧都要：`min-1`、`min`、`min+1`（max 同理），只测端点单侧会漏 off-by-one；
2. 异常用例区分「预期内异常」（返回错误码）与「预期外异常」（不应崩溃）；
3. 副作用用例要写清前置状态与清理方式，不然用例之间互相污染；
4. 不追求 100% 行覆盖——分支覆盖（尤其错误分支）比行数更有意义，写明取舍。

## 常见错误

先读 `references/pitfalls.md`。特别注意：只测 happy path、
异步代码只测 resolve 不测 reject、mock 掉了被测逻辑本身。
