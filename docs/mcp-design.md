# cn-reach MCP Server 设计稿（v0.2，未实现）

> 状态：**设计稿**。本文档是 v0.1（skills + CLI）之外的第二资产「中文互联网 MCP Server」的实现蓝图，尚未有代码。说明：文中对目标平台页面结构的描述基于 2025-2026 的公开观察，实现时必须以抓取实测为准。

## 定位

让 Agent 通过 MCP 协议读取中文互联网公开内容（知乎 / B 站 / 公众号），输出 LLM-ready Markdown。与通用网页阅读器的差异点：**中文页面正文抽取 + B 站字幕时间轴去重**两个自研算法点。

## 架构

```
Transport（stdio + Streamable HTTP 双模）
  → Tool Registry（5 个工具）
  → Fetch（undici 直连；Playwright 无头兜底）
      · 令牌桶限速默认 1 req/s（可配），尊重 robots.txt
      · 失败降级：缓存兜底返回并标注「可能过期」
  → Parse（正文抽取 / 字幕去重）
  → Cache（SQLite + TTL + ETag 条件请求）
  → Output（统一 Markdown/JSON）
```

## Tool 定义（5 个）

| tool | 输入 | 输出 | 备注 |
|---|---|---|---|
| `search` | query, platform, limit | 标题/链接/摘要/时间 | 公众号无公开搜索接口，见「合规边界」 |
| `read` | url | 正文 Markdown + 元数据 | 核心路径 |
| `comments` | url, limit | 评论列表 | 知乎需登录态的部分内容不承诺 |
| `trending` | platform, category | 热榜条目 | 知乎/微博热榜有公开端点 |
| `transcript` | bv_id | 带时间戳字幕 Markdown | B 站字幕 API 相对稳定 |

## 算法点 1：中文页面正文抽取（不直接套 readability）

readability 对中文信息流页面（推荐位/侧栏/评论区混排）失效率高，自研抽取流程：

1. DOM 构建（优先 cheerio 静态解析，动态渲染页才走 Playwright——成本差两个数量级）；
2. 块级节点文本密度 = 节点文本字符数 / (后代标签数 + 1)；
3. 标签路径聚类：`/div/div/p` 相同路径的节点聚成簇；
4. 剔除「路径频次高 + 密度低」的簇（自动识别导航/侧栏/推荐位）；
5. 密度 × 路径投票选出正文容器，容器内按广告特征 id/class 关键词表清理。

**失效自愈**：解析结果低于置信阈值时返回结构化错误而非垃圾文本；页面结构变化通过契约测试（录制回放）在 CI 捕获。

## 算法点 2：B 站字幕时间轴去重

1. 拉取 JSON 字幕轨（CC 优先，ai 字幕标注来源）；
2. 相邻行相似度（字符 overlap）> 0.8 合并（ai 字幕逐行断句导致大量重复）；
3. 相邻时间间隔 > 3s 插入段落分隔（对齐语义停顿）；
4. 输出 `[mm:ss]` 前缀 Markdown，Agent 引用可溯源到视频位置。

## 合规边界（是设计约束，不是免责声明）

- 只读公开数据；不绕登录态、不做验证码对抗。**由此产生的能力边界要写进 README**：
  - 公众号：无公开列表接口，搜索能力降级为「用户给文章 URL 后读取」，不承诺发现能力；
  - 知乎：部分内容登录可见，只承诺「未登录可见部分」；
  - B 站：字幕/视频元数据为公开接口，承诺度最高。
- 限速 1 req/s 默认值写死为安全侧，调高需显式配置；
- 声明「仅用于个人学习与研究」，不复分发抓取结果。
